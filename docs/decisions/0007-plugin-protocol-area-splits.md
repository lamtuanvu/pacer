# Plugin agent protocol area for the 0.2 SDK

The integrated M1 and M0 schemas generate 13,778 non-comment lines in the plugin root crate, exceeding CRATE-3's 10,000-line limit. An agent-only split measured root12,034/agent1,845; a dispatch-only split measured root10,579/dispatch3,267. A planner-only closure measured root10,589/planner3,293, also over limit. None fits alone. The chosen complete two-area split measures root8,835/agent1,845/dispatch3,267. The existing shared string validators already preserve distinct public types and validation. Limits, validation, and layer-0 peer dependency rules remain unchanged.

Generate the complete independent `agentSession.*` area (including inline native identity shapes) in publishable `pacer-plugin-agent-protocol` 0.2. Its schema definitions have no external `$ref` dependencies. Generate the complete independent observation/decision closure in publishable `pacer-plugin-dispatch-protocol` 0.2 as a second domain area. Keep generic lifecycle and `CallMetadata` in `pacer-plugin-protocol`; policy/read-only observations remain in the separate unpublished policy area. No layer-0 area depends on another.

The SDK layer depends on the three publishable protocol areas and exposes existing type names through `pacer_plugin::types`. Direct 0.2 root-protocol paths for agent and observation/decision types migrate to their respective new areas; this is an explicit pre-1.0 layout change. The immutable M1 0.1 source/release lane is unaffected. Neither the area split nor the facade implements policy brokers, owner lifetimes, or event delivery.

Publish the independent root, agent and dispatch protocol crates before the SDK. Package/archive checks and clean external-consumer compilation cover this graph. Generate every existing client, session, control, dispatch, plugin and policy area together, and retain fresh schema/type validation and size/dependency checks. Build timing evidence belongs to the integration report; no publication or merge is authorized by this decision.
