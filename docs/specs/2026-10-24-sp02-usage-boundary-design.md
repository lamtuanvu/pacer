# SP02 usage extraction: source-reconciled boundary

Status: proposed for coordinator/security review; no capability or reader implementation authorized by this document alone. Base `5f2f6219ed818fdd0ac1897fa36d3c2f37eca338` includes the public semantic oracle. Historical extraction spec §2 and SP02 plan describe the goal; current source controls behavior. This isolated future-version branch does not alter the frozen initial M1 release, publish artifacts, integrate/cut over released code, or waive initial SDK publication and M1 gates.

## Goal and boundaries

Extract the four usage readers into bundled pacer-usage, preserving current caller-visible UsageReading, timestamps, account identity, persistent fallback, large-log behavior and broker semantics. Keep diagnostic and agentSession methods/bundle; add usage rather than replacing existing points. There is no host built-in reader fallback after extraction. Reactive/unmetered paths remain in the host and never start a usage plugin. Missing/disabled/failing readers give readable unknown/unavailable results, without silently invoking retired implementations.

The host retains cache/aggregation/auth/exhausted marks/remote merge, account-home derivation and identity/evidence policy; Claude passive telemetry capture/final-result parsing/status-line cache writes; pure parsers needed for remote observation; and generic persistence machinery. Plugin owns reader interpretation, command selection, Codex observation/cursor aggregation, and provider-specific freshness/errors. Existing semantic fixtures remain unchanged as the oracle.

## Approaches and selected proposal

A narrow, explicitly named `usage.state` capability backed by host-fixed opaque stores preserves persistent cache/cursor operations and error timing without exposing filesystem writes. This is proposed over read-input/write-result snapshots, which make synchronous cache-write failure fallback and cursor serialization across overlapping calls difficult. In-memory-only cache loses existing restarted-process stale fallback and is rejected. Generic fs.write or hidden writes under fs.read are rejected. Coordinator prefers the narrow capability; security review must approve its exact contract before implementation.

## Wire contracts and version isolation

TypeScript src/plugins/protocol.ts stays canonical. Future wire is additive 1.1.0; future Rust SDK/protocol packages use distinct 0.2.0 versions on this branch. Never overwrite/rebuild initial published0.1.0 artifacts. TypeScript SDK remains private until separately authorized publication. Regenerate protocol markdown/schema and Rust protocol types with the existing generators, never edit generated Rust. Old1.0 plugins keep major-compatible hello, diagnostic/log/config and agentSession behavior. New authority-bearing capabilities require correlation and are unavailable to legacy uncorrelated calls; old methods do not gain account authority implicitly.

`usage.read` params project only provider id, redacted account identity (name/kind/source), selected model/weeklyTokens/weeklyUsd/quotaSource, host observation now/readOnly/refresh, and host-derived account home where needed. Never send full AccountCfg, connection object, arbitrary environment, credentials or secret values. Rich reading result preserves every current field: recursive alternatives, windows and stale, capturedAt/source/remoteHost/error/spendUsd, evidence arrays with id/scope/budgetPolicy/observedAt/validUntil/reason/value, availability and spending signals. Object schemas are additive/unknown-field-preserving. No transport timestamps refresh cached observation time.

## Call authority and lifetime

Each host extension request has an unpredictable call token carried in additive top-level RPC `_meta`, separate from provider params. PluginProcess owns token→authority records containing process generation, request id, approved paths/executables/stores, immutable account variables, grants, deadline and AbortSignal. SDK constructs a distinct HostClient for each handler and echoes that token on its capability requests; no entry-global mutable ACCOUNT_HOME. The host rejects absent/expired/wrong-generation tokens before filesystem reads, state mutation or spawn. Admission budgets: at most8active calls and32queued per registry; excess gives an explicit plugin-unavailable/unknown reading error, never fallback. Each active usage call owns at most1provider child,1state lease and1outstanding256KiB chunk; same store global serialization remains. Parent10s absolute deadline begins before queue/startup/backoff and includes assembly/cleanup; an expired queued call never starts a new request. Capability deadlines are min(method deadline, parent remaining). Request0 means no timer explicitly; usage remains bounded10seconds. The existing public cachedBase10s timeout may return an unknown/error reading while registry cleanup is still settling; that reading does not certify cleanup. Registry retains admission slots and state leases until owned settlement, and shutdown/live teardown awaits settlement. Admitted cleanup may finish after the authority deadline without renewing it.

On completed assembled reply/error/timeout/cancel/disable/exit/shutdown, revoke new authority admission first, abort child work, settle already-admitted commits and release state leases, and reap owned spawned children before declaring cleanup complete. Late callbacks cannot inherit a later account call. Progress is routed only to its still-active request id; unknown/late progress ignored. Track spawned children through actual exit/close; bounded SIGTERM then SIGKILL only for the owned unreaped child. No retries after ambiguous spawn/action delivery. An old or malicious subprocess is not an OS sandbox: tokens prevent stale accidental authority inheritance, not secrecy between handlers sharing one process. Tests must not describe correlation as isolating malicious code with OS access.

## Filesystem capabilities

Implement fs.read/list plus bounded fs.stat/read-range under fs.read, with explicit method mapping. Claude retains existing unbounded JSON-file semantics under the parent deadline; each wire read-range chunk is at most256KiB and uses nonnegative byte offset/length with base64 bytes so a UTF-8 boundary cannot change Codex parsing. A multi-chunk read pins the expected identity and size across chunks; rotation fails the logical read. Stat returns size, inode/device and mtime precision used by existing reusable rules. Range reads open once, fstat, verify expected identity, read at most requested cap and fstat again; rotation/truncation/identity changes yield a retryable observation failure rather than stale permission evidence. Return no bytes for rejected identity.

Host derives allowed resource descriptors for the current account, then intersects those with declared scopes and current grants. Claude: exact host-selected rate-limit cache paths and default .claude/state/budget/claude.json. Codex: only selected home/sessions directories and rollout-*.jsonl regular files; exclude native auth/config/credentials. Persistent provider caches are accessed through usage.state, not broad PACER_HOME reads. No bare $ACCOUNT_HOME or .codex blanket read authority. Scope variables expand from host config only; unset/relative/traversal/sibling paths refuse. Canonicalize roots and targets; require resolved containment, no symlink escapes, regular-file types, O_NOFOLLOW final open and matching fstat dev/inode with the prechecked target before reading. Revalidate root/ancestor identities around open/list. List validates every returned entry and glob, bounds count/work, never returns outside-scope paths. Standard Node APIs give conservative race detection; no claim of descriptor-rooted openat sandboxing against malicious concurrent filesystem rewrites. Fail closed on unresolved identity; no native helper/dependency added.

Codex retains 4,000,000-byte suffix, newest15 fallback regardless age, complete-line-only evidence, future-event rejection, equal-observation conflicts/alternatives, credit signals, incremental append and cursor invalidation on rotation/truncation/inode change. Never enlarge cap or whole-read logs to make a fixture pass.

## Spawn capability

Resolve arkcli/opencode via host-owned ctx.which and pin canonical executable path/dev/inode for the active call. Refuse arbitrary paths with allowed basename, wildcard, symlink substitution, changed executable, arbitrary cwd/env/stdin and unapproved argument shapes. For this extraction, allow only existing read-only commands: arkcli usage plan --product coding-plan and ['opencode', 'stats', '--models', '--cost', '--json', '--days', '7']. Host-owned provider child preserves the current defaultRun environment and process.cwd only for the two exact allowlisted commands on pinned executable identities. Root's explicit ruling preserves current ARK/OpenCode/XDG/profile/config selector behavior. The plugin never receives that environment or cwd in input/results, cannot choose overrides/stdin, and the plugin process itself retains its limited launch environment. This is existing provider-child inheritance, not a minimal-env or OS-sandbox claim. No secret resolver or caller-supplied secret references in SP02. The host never reads native credential stores or serializes credential contents to plugin params/results/logs. Plugin launch environment stays limited; trusted fixed-command provider-child ambient inheritance follows the explicit root ruling above.

Read stdout/stderr incrementally, cap each at1MiB, terminate/reap on cap/timeout/cancel, and report readable failure/stale fallback. Provider output may contain worst-case JSON escaping. Return opaque output handles plus256KiB read chunks under the same call lifetime if an encoded response would exceed the bounded wire message limit; SDK reconstructs exact UTF-8 using streaming decoding. No blanket1MiB plugin-output frame-cap increase. Bound SDK input buffering and staged handles explicitly, preserve legacy small replies. Parent10s bounds metered's historical15s child budget just as current host's10s source race; unlike the old race, timed-out children are owned and cleaned. If cleanup changes any oracle-visible timing/error semantics, record it for explicit review rather than suppressing it.

## Host-owned opaque state

Add capability name `usage.state` with methods begin/readChunk/stageChunk/commit/release, explicitly declared/granted. The host supplies available named-store descriptors in call authority; plugin chooses only an opaque handle, never a path/key belonging to another account/plugin. For this bundled extraction descriptors map to existing exact compatibility files: provider caches arkcli-usage-plan/opencode-stats-7d-cost and version4 Codex cursors. Host machinery is generic (versioned JSON value, atomic file replacement, private modes, serializer), while the plugin chooses provider interpretation/TTL and validates aggregate shape. No provider-specific host reader fallback.

Provider cache begin reads current snapshot per call without a new long lock; preserve existing cachedFetch last-atomic-writer semantics. SDK helper preserves600s/300s TTL and6h max stale, clock rollback, refresh bypass, readOnly, capturedAt and write-error-as-fetch-failure behavior. Commit for provider cache propagates persistence errors so the same helper returns the same stale/error result. Store identity/path is fixed by host; payload JSON-only and transferred in bounded chunks; no arbitrary config/credentials admitted to descriptors. Existing host plugin-output frame cap is1MiB: begin returns lease+length metadata, readChunk returns at most256KiB base64, stageChunk accepts contiguous bounded byte chunks under that lease, and commit accepts only a complete parsed JSON value with host-fixed store shape and chunk limits. Staging uses bounded per-call chunk windows plus host-fixed private temporary files, never caller-selected paths; drop on cancellation. SDK hides chunk assembly. There is no new4MiB total state cap: current CursorStore has no absolute size bound, retains all account roots, and full rateLimits/equal-time alternatives can grow across incremental updates. The4,000,000-byte suffix policy belongs only to Codex log interpretation; neither Claude JSON files nor compatibility state gain a new total-size cap. State transfer is paged by authorized current-root entry (newest15 source logs), with256KiB chunks, one outstanding chunk per call, one global cursor lease, at most8active/32queued calls,1lease+1outstandingchunk per active call, and10s parent deadline. Host preserves otherroot records without serializing them to this plugin call. Commit stages chunks to a host-owned private temporary under the existing state/cache directory where writable; readOnly state updates remain in memory just as current CursorStore. Parse/serialization is incremental by entry to avoid a second full-global-store copy; before each step check call budget/cancellation. Writable staging lives only under host-fixed private temp directories with0700 directories/wx0600 files; readOnly uses disposable host temp rather than writing persistent cache paths. Admission checks available disk before each256KiB append and leaves an8MiB free-space reserve; ENOSPC/quota failures preserve the old committed store and dirty retry state, produce explicit error rather than truncated success, and clean staging. This is a transfer resource failure, not an invented maximum compatibility-state size. Existing host cache memory consumption has no source-defined absolute ceiling; do not invent one or promise complete constant-memory compatibility. Oversized/deadline work fails explicitly without altering the prior persistent state or truncating alternatives. Tests must cover a valid global snapshot above4MiB with small current-root projection and a current-root entry above4MiB preserving equal-time alternatives. An absolute aggregate ceiling would be a separately reviewed compatibility change, not silently introduced by this extraction.

Cursor begin serializes by the global host-owned version4 Codex store identity, matching current CursorStore.run. That existing file contains multiple account roots. Before sending any snapshot, host projects only entries under this call's authorized canonical sessions root; no other account path/aggregate is visible. Lease snapshot includes validated projected version/state and dirty marker. On commit, validate every key is an authorized regular-log path and merge the account-root projection/deletions into the full host-owned snapshot, preserving all other roots, under the global lease. Filtered projection is not a separate database/file or a license to erase unrelated account records. Plugin applies current aggregate/reusable rules; commit updates in-memory host cache even in readOnly, suppresses disk writes in readOnly, persists dirty state0600 via wx+rename otherwise, and preserves dirty state after failed persistence. Cursor persistence failure returns a typed not-saved outcome that SDK suppresses exactly as current CursorStore; it must not discard a successful reading. Wrong version/corrupt state rebuilds conservatively. Release/cancel must unblock next lease; a rejected/late lease cannot commit after a successor starts. Persist only completed reader work. Commit/revocation linearization is explicit: acquiring the store commit gate while authority is active admits one atomic replacement; once revoke wins no new commit may start. An already-issued filesystem rename cannot be cancelled and may finish after the wall-clock deadline. Revocation/cleanup waits for admitted commit settlement before releasing the lease or permitting a successor; late staged commits refuse. Do not claim literal zero writes after expiration from an earlier token check. Cross-process last-writer cursor loss may cause extra reads, as today, not incorrect readings. Test overlap/cancel/error/readOnly then writable retry and cache restart explicitly.

## Rich result framing and negotiation

The complete rich usage result can itself exceed1MiB through equal-time alternatives. A1.1 peer explicitly advertises chunk-result support in additive hello features before either side uses chunked envelopes; old1.0 peers receive ordinary diagnostic/agentSession replies unchanged. Negotiated usage results send correlated result chunks (at most256KiB base64) plus a final completion envelope declaring exact encoded byte count/sequence. Host binds staging to process generation+request token+id, rejects missing/out-of-order/repeated/late chunks, assembles/validates the complete result before resolving the request, and keeps parent authority/deadline until assembly settles. No chunk can attach to a successor. Partial data never becomes an ordinary reading. Transport chunks/staging use the same numeric transient budgets/disk policy; final accepted rich object retains inherited caller memory semantics, with no claim of absolute aggregate-memory cap. Oracles cover >1MiB rich results, >4MiB global cursor stores and >4MiB current-account state, preserving unknown fields/conflict alternatives. Chunk details need canonical schemas/tests before transport implementation, separate from Task1's metadata/schema surface.
