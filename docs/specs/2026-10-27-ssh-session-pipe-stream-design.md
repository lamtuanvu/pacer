# Bounded remote session stream authority

## Context

Full remote sessions still use direct `ssh -O forward/cancel` commands and a direct `SESSION_PIPE` SSH child when forwarding is unavailable. The tracked SSH extraction design assigns session streaming to `hostRunner.stream` with bytes delivered through `$/progress`. The current schema reserves that name but has no duplex framing, acknowledgement or process lifetime contract. A forwarding-only migration would leave the session byte path outside the plugin contract.

## Decision

The host issues a one-use stream grant for an exact persisted task/run, configured SSH alias and host fingerprint, local run directory, fixed `SESSION_PIPE` script and remote run directory. The grant is consumed for one local viewer connection. Admission checks the task revision as well as the run tuple. During a live stream, ordinary REPORT polls may advance that revision; liveness instead rechecks the persisted run fingerprint/attempt, viewer ownership, host mapping, provider generation and private control directory. A changed run identity or owner revokes the stream. The provider may ask the broker to open only the pinned SSH argv, with `BatchMode`, the existing SSH-configured host-key policy and the sandbox context environment. The remote fixed script reads the uploaded session binary and socket path; it accepts no caller shell or arbitrary path. Public or unissued calls to the stream and duplex process capability are denied.

The broker owns one duplex SSH child for the stream call. Its private process handle exists only while that host call's authority is active; revocation terminates and reaps the process group. It caps each stdin write and stdout read at 64 KiB and has no disk stage. The bundled provider cannot select a different command, inherit ambient environment or persist a process handle after the call. The provider drives the pinned child through scoped `capability.process.duplex.open/read/write/close` operations, rather than spawning SSH itself. Existing capability calls use an exclusive owner lock. Duplex operations receive a stream-only exception that permits one pending read and one pending write concurrently on the same pinned handle, with no second operation of either kind; all other capabilities keep the exclusive lock.

The provider sends stdout as `$/progress` events with a stream ID, monotonically increasing sequence number and at most 64 KiB of base64 bytes. Existing `$/progress` callbacks are fire-and-forget, so this stream adds a private, call-scoped acknowledgement method. The host verifies the active call ID, stream ID, sequence and decoded length; it writes the bytes to the local viewer socket and acknowledges only after the socket accepts or drains them. The provider waits for that acknowledgement before sending another progress frame. For viewer input, the host sends one `$/streamInput` notification at a time with the original numeric request ID, stream ID, sequence and at most 64 KiB of base64 bytes. The SDK exposes this queue only to the owned `hostRunner.stream` handler. After the bundled provider's brokered SSH stdin write accepts or drains the bytes, it sends `$/streamInputAck` with the exact call metadata; the host admits the next input frame only after that acknowledgement. These notification and acknowledgement names are scoped transport messages, never independent capability grants. `hello`, control, resize and input frames remain opaque bytes; neither side interprets them in the bridge. Each JSON-RPC frame stays below the protocol's 1 MiB complete-frame limit. The bound is on in-flight memory, not total session bytes: each direction has one 64 KiB unacknowledged chunk plus fixed decoder/socket buffers, and a long session may transfer more. The host never records session bytes in RPC diagnostics or evidence.

`timeoutMs` bounds each pending read/write and acknowledgement, not the whole interactive session. The bundled session provider requires a per-I/O timeout of at least two seconds so its one-second idle poll completes before that deadline. An optional read poll of at most one second returns empty bytes with `eof: false` when idle; only stream closure returns `eof: true`. The provider repeats idle polls, and a read without a poll still fails closed on its finite timeout. `PluginRegistry.call` currently imposes a finite whole-call deadline on all hostRunner methods; only host-issued `hostRunner.stream` receives an owner-bound lifetime exception. Its process request has no wall-clock deadline, while its authority remains finite in representation and is revoked on viewer/run/provider/service ownership loss. Every pending I/O and acknowledgement has a finite timeout; an idle viewer is allowed. On true EOF, the provider accepts completion only after the broker observes the SSH child close with exit code zero, no signal, and no host termination; an uncertain or nonzero exit closes the viewer. Other hostRunner methods still require and enforce their existing finite deadlines. A viewer detach, task exit, provider crash, host drift, service exit, read/write timeout, bad sequence or malformed base64 closes the local viewer and revokes the owning authority, terminating and reaping the SSH child. The remote task continues; a new viewer may obtain a new grant and reconnect. An uncertain write is never replayed into the same session. No direct `ssh -O` or `SESSION_PIPE` fallback follows any refusal or failure. The `SESSION_PIPE` script identifier remains for wire compatibility.

## Delivery order

1. Add the duplex process capability and SDK stream/progress handshake behind a private feature flag, with negative tests for unissued access, command substitution, wrong call ID, child cleanup on service exit, in-flight memory, one-read/one-write concurrency, refusal of a second same-direction operation, task-revision churn with an unchanged run tuple and refusal of unbounded deadlines for every other hostRunner method. Existing fire-and-forget progress callers and exclusive capability calls retain their behavior.
2. Add the generated protocol types and bundled SSH provider implementation, with sequence/ack, timeout and malformed-frame tests. Update protocol docs and Rust generation together.
3. Switch `RemoteSession` to the host-issued stream, removing direct forwarding and direct exec paths only after session snapshot, control, resize, reconnect and cancellation tests pass.
4. Exercise a disposable real SSH full-session viewer through the guarded live harness; record remote task completion and any unexercised failure paths separately.

The bridge must retain its existing read-only viewer and control semantics. The current direct path remains active until the replacement is reviewed and validated; a partially implemented transport does not claim SP08 completion.
