# Workspace-first task experience

Approved scope: primary task links on Dispatch and Tasks open the selected task's workspace in every state. Successful creation opens the returned task ID immediately. Existing history routes remain available as secondary Task history links; diagnostic links and breadcrumbs retain their destinations.

The composer starts with outcome, repository, success checks and Start task. New tasks default to an isolated worktree. Advanced options retain branch, workspace, kind and executor overrides and saved drafts. Attachments and issue import remain available. Enabled commands run as acceptance checks; descriptive checks are instructions to the agent. No configured checks means no automatic verification promise.

Routing shows the likely agent. Fallback, model and budget information belongs in a disclosure. Unavailable executors are excluded from fallback suggestions; warnings are deduplicated and start-affecting issues stay visible.

The workspace preserves task identity across queued, running, needs-input and final states. Queued tasks show the service's recorded reason and next step without an invented ETA or queue position. A real session appears when available. Opening a workspace watches output without requesting control. Take control is secondary, Hand back releases control, and Stop task describes its scope. Completed tasks show results and changes; failed tasks offer actionable recovery; stopped tasks remain stopped.

Unknown metrics remain unavailable rather than becoming zero. Shared design-system controls, status vocabulary, accessible names and focus behavior apply. Task and session queries follow service events, with no polling loops.

Validation: focused regressions, typecheck, UI policy check, generated app build, browser evidence at 1440 light/dark and 375, and sandboxed live harness evidence. VoiceOver is waived under VO-TEMP-2026-10. Independent review is required before completion; an executor without a service grant hands off that gate to its planner.
