File viewer · interaction notes

A read-only look at a file the agent mentioned, without leaving or pausing the session. The numbers match the markers on the desktop board.

On the desktop board

1Path links. Workspace-relative paths, with an optional :line or :line:col, are underlined in the terminal. One click opens them. Bare words, URLs and paths outside the workspace are not linked. 2Opens as a side-panel tab. The terminal keeps its size, its scroll position and its keyboard control. Opening another path replaces the file tab. ⌘-click opens it in an extra tab instead. 3Read-only, always. There is no edit mode. Copy path and Open in editor hand off to the user’s own tools. 4Back to terminal Esc returns focus to the exact terminal pane and cursor. The tab stays open for later. 5Where you are. Worktree name, then the path. A Line chip appears when the link carried a line. “Session running” confirms that nothing paused. 6Target line. The linked line is tinted and its number made bold, and it scrolls to the upper third of the view. Search matches are tinted, and the current match is solid.

Opening and focus

  • Pointer. A click on a link opens the viewer and moves focus to its body. The terminal stays interactive, and typed keys still reach it once focus is back.
  • Keyboard. ⌃⇧O in the terminal opens the last path printed. ⌃⇧L lists every path in the visible scrollback to choose from.
  • Focus order inside. Back to terminal, search, copy, open in editor, the Source/Preview tabs, then the body. The body is a focusable region, so arrow keys and Page Up/Down scroll it.
  • Never steals input. The viewer never opens on its own when output arrives. Only the user’s click or key opens it.
  • Closing a tab with × or ⌘W returns focus to the terminal.

States

  • Loading. Filename and path appear at once. The skeleton appears only after 150 ms, so fast reads don’t flash. A polite status reads “Reading src/main.ts…”.
  • Missing. Names the path and the workspace that were checked, then offers to find similar names and to retry. Paths outside the workspace get the same state with “outside this workspace” in the text.
  • Large. Over 5 MB or 50,000 lines: the first 2,000 lines, rendered virtually. Search covers the lines loaded and says so. Loading more is always explicit.
  • Unsupported. NUL bytes or a binary MIME type. Nothing is rendered; it hands off to Open in editor or Reveal in Finder.
  • Changed on disk. A quiet notice, “The agent changed this file · Reload”. The scroll position is never yanked.

Preview isolation

  • HTML renders in a sandboxed iframe with no allow-scripts and no allow-same-origin, on a separate origin. It gets a CSP of default-src 'none'; style-src 'unsafe-inline'; img-src data:, so the frame cannot reach pacer, cookies, the session or the network.
  • The banner lists every blocked script and request by type and address, so a page that looks broken explains itself. Links inside the frame do nothing; the address is shown instead.
  • Markdown is sanitised. Raw HTML is dropped, remote images become labelled placeholders, and relative links to workspace files open in the viewer.
  • Source is the default tab. Nothing renders until the user picks Preview.

Layout and accessibility

  • 1100 px and up. A side-panel tab, 560 px wide by default, resizable between 400 px and half the window.
  • 768–1099 px. The panel overlays the details column at 480 px.
  • Below 768 px. A full-screen sheet with Back to Terminal at the top left and 44 px touch targets.
  • Semantics. The viewer is a labelled region (“File viewer: src/main.ts”). The source is announced by line, and line numbers are hidden from screen readers. Status always comes with words, never colour alone.
  • Colour. Syntax colours come from status tokens and meet 4.5:1 in both themes. Reduced motion stops the loading shimmer.
