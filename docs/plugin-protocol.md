# Plugin protocol v1.0.0

Generated by `bun run plugin:protocol`. Check freshness with `bun scripts/plugin-protocol-doc.ts --check`. The JSON Schema for every message is in [plugin-protocol.schema.json](plugin-protocol.schema.json).

## Overview

A plugin is a subprocess the host starts lazily. Both sides speak newline-delimited JSON-RPC 2.0 on the plugin's stdin and stdout (one object per line, 1 MiB cap). stderr is captured to `$PACER_HOME/logs/plugins/<id>.log`. Both sides send requests, so each side matches replies by id. Additive changes do not bump the version; removals bump the major, and the host serves the previous major for one pacer minor release.

The host sends `plugin.hello` first and refuses a plugin whose reply has a different protocol major, or an id or version that differs from its manifest. Every call carries a deadline owned by the host; on expiry it sends the notification `$/cancel` with `{ id }`, fails the call with `plugin_timeout` and drops any later reply.

## Lifecycle

States: `disabled`, `refused`, `needs_grant`, `idle`, `starting`, `ready`, `failing`. Bundled plugins are enabled unless listed in `plugins.disabled`; installed plugins need a recorded grant covering their capability set and drop back to `needs_grant` when a new version asks for more. A crash restarts the plugin after 1 s, doubling to 30 s; three crashes within a minute mark it `failing` until `plugin.enable` or a service restart. Calls to one plugin run one at a time unless the manifest sets `reentrant`. Service stop sends SIGTERM, then SIGKILL after 2 s.

## Errors

| Code | Meaning |
|---|---|
| `plugin_timeout` | A call passed its deadline. |
| `plugin_unavailable` | The plugin is disabled, refused, needs a grant, is failing, or exited mid-call. |
| `plugin_refused` | Manifest or handshake rejected. |
| `capability_denied` | Capability not declared, not granted, or outside its scope. |
| `unknown_plugin` | No plugin with that id. |

Plugin replies use JSON-RPC errors `{ code: -32000, message, data: { code, hint? } }`; a `data.code` the host knows is passed through, anything else becomes `plugin_unavailable`.

## Capabilities (plugin → host)

Answered only when the manifest declares the capability and, for installed plugins, the grant covers it.

### `capability.log`
