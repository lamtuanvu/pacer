# pacer context index

Updated: 2026-10-19. The entry point for agents and contributors. Load this file and [constitution.md](constitution.md), then only the rules and reviewers that match the paths your change touches.

## Purpose

pacer paces AI coding work across subscription budgets. A planner plans and reviews, while executors do the execution under supervision. See [README.md](../README.md), [ROADMAP.md](../ROADMAP.md) and [docs/README.md](../docs/README.md).

## Architecture map

| Path | Component |
|------|-----------|
| `src/cli.ts`, `src/commands/` | CLI dispatcher and subcommands. Compiled into the bun CLI `dist/pacer-core`; the Rust front door `dist/pacer` execs it when a command is not yet native. |
| `src/api/` | Versioned protocol (`protocol.ts`, now 3.0.0), operation registry (`ops.ts`), HTTP and stdio JSON-RPC transports, `v2-compat` adapter, read model |
| `src/serve/`, `src/service/` | The local service: HTTP/SSE/WebSocket, app auth and panel. Installed under launchd or as a systemd user unit. |
| `src/core/`, `src/engine/`, `src/tasks/`, `src/strategy/`, `src/config/` | Domain core: ranking, slots, verdicts, tasks, strategy and config. `CoreError` lives in `src/core/errors.ts`. |
| `src/usage/` | Usage broker: cache, aggregation, auth/exhausted marks and remote merge; quota and metered readers live in `plugins/pacer-usage/` |
| `src/attention/`, `src/activity/`, `src/notify/`, `src/jobs/` | Attention, activity log (JSONL, mode 0600), notifications, jobs |
| `src/exec/`, `src/supervisor/`, `src/remote/`, `src/session/` | Execution backends (direct, Orca), supervised runs and worktrees, SSH remote hosts, PTY live sessions |
| `src/endpoints/`, `src/install/`, `src/mcp/`, `src/update/` | OpenAI-compatible endpoint executors and their keys, planner hook installers, MCP server, self-update |
| `src/dashboard/`, `src/render/`, `src/view-model/` | TUI, status line and tables, shared view vocabulary |
| `src/plugins/` | Plugin host: protocol schemas, manifest, registry and lifecycle, stdio subprocess transport, capability broker, `pacer plugin run` |
| `plugins/` | Bundled reference plugins (`plugins/bundled.ts`), compiled into the binary |
| `packages/plugin-sdk/` | `@pacer/plugin`, the plugin-side runtime (bun workspace) |
| `conformance/` | Host-neutral plugin conformance suite and fixture plugins; run by `test/plugin-conformance.test.ts` |
| `src/link/`, `src/console/` | Remnants of the transport retired in 3.0 (see open decisions) |
| `app/` | Preact web UI and tray popover served at `/app/`, with its design system in `app/src/ds/`. The bundle is embedded in `src/app/assets.generated.ts`. |
| `desktop/` | Tauri v2 macOS shell that loads the service's `/app/` |
| `npm/launcher/` | npm launcher that picks the platform package |
| `scripts/` | Release, protocol-doc, e2e, QA, brand and design-system sync scripts |
| `test/` | Flat `bun:test` suite (`<area>-<topic>.test.ts`), `fixtures/`, `__snapshots__/`; `test/setup.ts` isolates `HOME`/`PACER_HOME` |
| `crates/foundation` | `pacer-foundation`: ctx, file rules, lock, `CoreError`, op registry types |
| `crates/session-protocol` | `pacer-session-protocol`: generated interactive-session operation types, split from the client schema under CRATE-3 |
| `crates/cli` | `pacer-cli`: argv dispatch, core exec, status line, self-repair |
| `crates/pacer` | `pacer`: the binary, start-up and dispatch only |
| `crates/plugin-sdk` | `pacer-plugin`: Rust plugin SDK |
| `crates/fixtures` | `pacer-fixtures`: Rust conformance fixture plugins |

Dependency direction: clients → `src/api` → core → adapters. Source: [ADR clients-over-local-service](../docs/decisions/2026-10-16-clients-over-local-service.md).

## Commands

These come from the configuration listed in Source. None were run while this index was written.

| Purpose | Command | Source |
|---------|---------|--------|
| Install | `bun install --frozen-lockfile` | CONTRIBUTING.md, ci.yml |
| Typecheck | `bun run typecheck` (`tsc --noEmit && tsc -p app`) | package.json |
| Test | `bun run test` (pins `TZ=Asia/Ho_Chi_Minh`; plain `bun test` gives unreliable date results) | package.json, CONTRIBUTING.md |
| UI policy and PR evidence | `bun run ui:check` | scripts/ui-check.ts; ci.yml |
| Build binary | `bun run build` | package.json |
| Rebuild generated assets | `bun run app:build`, `bun run protocol:doc` | package.json, CONTRIBUTING.md |
| Plugin protocol docs | `bun run plugin:protocol` | package.json |
| Release | `bun run release:prepare <x.y.z>` → PR `chore: release x.y.z` → dry-run dispatch → tag `v<x.y.z>` | CONTRIBUTING.md |
| Desktop | `cargo test --offline`; `bunx tauri build --no-sign` (in `desktop/`) | desktop/README.md |
| Rust build | `cargo build --workspace` | ci.yml, CONTRIBUTING.md |
| Rust test | `cargo test --workspace --locked` (also in the rust CI job) | ci.yml, CONTRIBUTING.md |
| Generate Rust code | `cargo xtask gen` (`cargo xtask gen --check` verifies it is fresh) | ci.yml, rules/rust.md |
| Crate sizes | `cargo xtask loc` (`cargo xtask loc --check` in CI) | ci.yml, rules/rust-crates.md |
| Crate layers and heavy deps | `cargo xtask deps` | ci.yml, rules/rust-crates.md |
| Live validation | `bun run live up`, then drive the surfaces, `bun run live report`, `bun run live down --keep` | docs/testing/live-validation.md |

There is no lint or format command; `.editorconfig` is the only style config.

## Reviewer index

The human approver for every merge is @lamtuanvu. Amendment 0.4.0 proposes required UI/accessibility and QA evidence for UI-affecting changes; adoption occurs only when the maintainer merges that amendment. Recommendations and other reviewers remain advisory. Read the constitution for the evidence contract; reviewers cannot grant approval or exceptions.

| Reviewer | Triggers | Definition | Role and gate |
|----------|----------|------------|---------------|
| Architecture | New surface or capability; changes across `src/api` ↔ core ↔ clients; new ADR; a new Rust crate, a crate dependency, or a crate past 8,000 LOC (CRATE-1) | [reviewers/architecture.md](reviewers/architecture.md) | Advisory |
| Protocol compatibility | `src/api/**`, `src/serve/**`, `docs/protocol*.md`, client API reads | [reviewers/protocol-compat.md](reviewers/protocol-compat.md) | Advisory |
| Security | Paths in the security rule; new subprocess, network, file-permission or secret handling | [reviewers/security.md](reviewers/security.md) | Advisory |
| QA & tests | Any behavior change in `src/`, `app/` or `desktop/` | [reviewers/qa.md](reviewers/qa.md) | Advisory; UI-affecting changes require a report under amendment 0.4.0 |
| UI & accessibility | `app/**`, TUI rendering, desktop shell | [reviewers/ui-accessibility.md](reviewers/ui-accessibility.md) | Required UI evidence report under amendment 0.4.0; human approves merge |
| Release | Version bumps, CHANGELOG, release scripts and workflows, distribution packages | [reviewers/release.md](reviewers/release.md) | Advisory |

Docs-only changes need just the repository rule, plus the protocol reviewer when `docs/protocol*.md` changes.
