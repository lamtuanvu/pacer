# pacer context index

Updated: 2026-10-18. The entry point for agents and contributors. Load this file and [constitution.md](constitution.md), then only the rules and reviewers that match the paths your change touches.

## Purpose

pacer paces AI coding work across subscription budgets. A planner plans and reviews, while executors do the execution under supervision. See [README.md](../README.md), [ROADMAP.md](../ROADMAP.md) and [docs/README.md](../docs/README.md).

## Architecture map

| Path | Component |
|------|-----------|
| `src/cli.ts`, `src/commands/` | CLI dispatcher and subcommands. Compiled into a single `dist/pacer` binary. |
| `src/api/` | Versioned protocol (`protocol.ts`, now 3.0.0), operation registry (`ops.ts`), HTTP and stdio JSON-RPC transports, `v2-compat` adapter, read model |
| `src/serve/`, `src/service/` | The local service: HTTP/SSE/WebSocket, app auth and panel. Installed under launchd or as a systemd user unit. |
| `src/core/`, `src/engine/`, `src/tasks/`, `src/strategy/`, `src/config/` | Domain core: ranking, slots, verdicts, tasks, strategy and config. `CoreError` lives in `src/core/errors.ts`. |
| `src/usage/`, `src/attention/`, `src/activity/`, `src/notify/`, `src/jobs/` | Usage readers, attention, activity log (JSONL, mode 0600), notifications, jobs |
| `src/exec/`, `src/supervisor/`, `src/remote/`, `src/session/` | Execution backends (direct, Orca), supervised runs and worktrees, SSH remote hosts, PTY live sessions |
| `src/endpoints/`, `src/install/`, `src/mcp/`, `src/update/` | OpenAI-compatible endpoint executors and their keys, planner hook installers, MCP server, self-update |
| `src/dashboard/`, `src/render/`, `src/view-model/` | TUI, status line and tables, shared view vocabulary |
| `src/link/`, `src/console/` | Remnants of the transport retired in 3.0 (see open decisions) |
| `app/` | Preact web UI and tray popover served at `/app/`, with its design system in `app/src/ds/`. The bundle is embedded in `src/app/assets.generated.ts`. |
| `orca-plugin/` | Orca worker plus static, information-only panel. `dist/` is committed generated output. |
| `desktop/` | Tauri v2 macOS shell that loads the service's `/app/` |
| `npm/launcher/` | npm launcher that picks the platform package |
| `scripts/` | Release, protocol-doc, e2e, QA, brand and design-system sync scripts |
| `test/` | Flat `bun:test` suite (`<area>-<topic>.test.ts`), `fixtures/`, `__snapshots__/`; `test/setup.ts` isolates `HOME`/`PACER_HOME` |

Dependency direction: clients → `src/api` → core → adapters. Source: [ADR clients-over-local-service](../docs/decisions/2026-10-16-clients-over-local-service.md).

## Commands

These come from the configuration listed in Source. None were run while this index was written.

| Purpose | Command | Source |
|---------|---------|--------|
| Install | `bun install --frozen-lockfile` | CONTRIBUTING.md, ci.yml |
| Typecheck | `bun run typecheck` (`tsc --noEmit && tsc -p app`) | package.json |
| Test | `bun run test` (pins `TZ=Asia/Ho_Chi_Minh`; plain `bun test` gives unreliable date results) | package.json, CONTRIBUTING.md |
| Build binary | `bun run build` | package.json |
| Rebuild generated assets | `bun run plugin:build`, `bun run app:build`, `bun run protocol:doc` | package.json, CONTRIBUTING.md |
| Release | `bun run release:prepare <x.y.z>` → PR `chore: release x.y.z` → dry-run dispatch → tag `v<x.y.z>` | CONTRIBUTING.md |
| Desktop | `cargo test --offline`; `bunx tauri build --no-sign` (in `desktop/`) | desktop/README.md |
| Live validation | `bun run live up`, then drive the surfaces, `bun run live report`, `bun run live down --keep` | docs/testing/live-validation.md |
| Orca e2e | `scripts/e2e/orca-bootstrap.ts` (outside `bun test`) | docs/testing/orca-e2e.md |

There is no lint or format command; `.editorconfig` is the only style config.

## Reviewer index

All reviewers are advisory (constitution, "Validation and review agreements"). The human approver for every merge is @lamtuanvu.

| Reviewer | Triggers | Definition | Role and gate |
|----------|----------|------------|---------------|
| Architecture | New surface or capability; changes across `src/api` ↔ core ↔ clients; new ADR | [reviewers/architecture.md](reviewers/architecture.md) | Advisory |
| Protocol compatibility | `src/api/**`, `src/serve/**`, `docs/protocol*.md`, client API reads | [reviewers/protocol-compat.md](reviewers/protocol-compat.md) | Advisory |
| Security | Paths in the security rule; new subprocess, network, file-permission or secret handling | [reviewers/security.md](reviewers/security.md) | Advisory |
| QA & tests | Any behavior change in `src/`, `app/` or `orca-plugin/` | [reviewers/qa.md](reviewers/qa.md) | Advisory |
| UI & accessibility | `app/**`, TUI rendering, Orca panel HTML, desktop shell | [reviewers/ui-accessibility.md](reviewers/ui-accessibility.md) | Advisory |
| Release | Version bumps, CHANGELOG, release scripts and workflows, distribution packages | [reviewers/release.md](reviewers/release.md) | Advisory |

Docs-only changes need just the repository rule, plus the protocol reviewer when `docs/protocol*.md` changes.
