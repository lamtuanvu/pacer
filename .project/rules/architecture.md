# Architecture rules

Applies to: `src/**`, `app/**` and `desktop/**`. Also applies to any change that adds a capability, a client surface or an execution backend.
Out of scope: internal refactors inside one module that leave its imports and public operations unchanged.
Owner: @lamtuanvu
Canonical sources: [ADR Rust front door and coexistence](../../docs/decisions/0004-rust-front-door-and-coexistence.md), [ADR plugin-host-and-rust-strangler](../../docs/decisions/2026-10-19-plugin-host-and-rust-strangler.md), [ADR clients-over-local-service](../../docs/decisions/2026-10-16-clients-over-local-service.md), [ADR retire-orca-plugin](../../docs/decisions/2026-10-20-retire-orca-plugin.md), [ADR remote-hosts-ssh](../../docs/decisions/2026-10-15-remote-hosts-ssh.md), [core contract spec](../../docs/specs/2026-10-14-core-contract-design.md), `test/core-boundaries.test.ts`

| ID | Rule or convention | Status | Rationale/source | Verification |
|----|--------------------|--------|------------------|--------------|
| ARCH-1 | `pacer serve` owns work and state. Clients (CLI, TUI, web/tray, desktop) read and act only through the versioned API operations and events, never through private files or internal modules of the service. | Established | Clients ADR D1–D2 | Review imports from client code. `test/view-model-client-migration.test.ts` |
| ARCH-2 | A new capability goes in the core as an operation or event first. Clients come after. | Established | Clients ADR D2 | Review: the diff adds an op in `src/api/ops.ts` before client use |
| ARCH-3 | Operations are multi-client safe. A conflicting concurrent change returns a `conflict` error instead of a last-write-wins overwrite. | Established | Clients ADR | Tests for concurrent ops |
| ARCH-4 | `src/core` never imports `src/exec/orca`. (0.5.0 removed the `orca-plugin/` clause with the plugin.) | Established | core-boundaries test | `bun run test` (core-boundaries) |
| ARCH-5 | Nothing assumes a fixed planner (Claude) or host (Orca). Planner and host integrations live behind installers or adapters. | Established | Clients ADR; ROADMAP | Review for hard-coded planner and host names in the core |
| ARCH-6 | Retired (0.5.0). Was: the Orca plugin only shows information. The Orca plugin is removed. | Retired (0.5.0) | ADR retire-orca-plugin | — |
| ARCH-7 | Remote hosts are driven over SSH (BatchMode) with no pacer or Bun installed on them. Results return as a verified git bundle, and acceptance runs locally. | Established | Remote-hosts ADR | `test/remote-*` tests; review |
| ARCH-8 | The CLI and TUI stay complete and need no other surface. | Established | Clients ADR | Review |
| ARCH-9 | Durable architectural choices get an ADR in `docs/decisions/`. | Established | GOVERNANCE.md | Review the PR for a matching ADR |
| ARCH-10 | Remove retired transport code (`src/link/`, `src/console/`, the `link/consoles` watcher) or move what is still used (e.g. `OutboxEvent`) into its owning module. | Proposed | 3.0 retired the link transport (#77) | Pending decision |
| ARCH-11 | Rename phase-numbered modules (`src/commands/plan2b.ts`…`plan7.ts`) after what they do. | Proposed | Observed naming drift | Pending decision |
| ARCH-12 | The host is minimal: a capability a plugin could provide goes in a plugin against the plugin protocol, and once extracted the host has no built-in fallback. Routing, strategy and the pacing engine stay in the host. | Established | ADR plugin-host-and-rust-strangler D1 | Review; `plugin.list` shows the provider of each capability |
| ARCH-13 | Only `src/plugins/` and `src/core/plugins.ts` import the bundled plugin list. Plugins never import host code; they use `@pacer/plugin`. | Established | same ADR | `bun run test` (core-boundaries) |
| ARCH-14 | The plugin protocol follows API-1 to API-4: additive changes need no bump, removals bump the major, docs are generated and freshness-tested, errors are `CoreError` codes. | Established | same ADR; P14 | `test/plugins-protocol-doc.test.ts` |
| ARCH-15 | During M1/M2, the Rust front door owns public client transport entry points: stdio, loopback HTTP/SSE/WebSocket, and the public native listener in supported signed paired apps. Operations and routes not yet native forward to the supervised TypeScript core with existing public request/result/error, authentication and event semantics. Core listeners and control channels are private implementation interfaces, not alternate public service entry points. | Proposed (amendment 0.10.0) | ADR 0004; migration spec §§0.1, 1.4–1.5 | Artifact parity/conformance; CT-11; signed old-helper audit-identity and recovery proof |
| ARCH-16 | During coexistence, durable shared state uses established formats and concurrency protocols: atomic file replacement and shared operation locks where applicable, and the existing SQLite schema, transactions, WAL, busy timeout, JSON write-through/import recovery and retention compatibility for task state. A port must not create a second database or weaken recovery/rollback guarantees. Authenticated private IPC may coordinate transient runtime state and capabilities; it does not replace durable persistence contracts or permit direct client state access. | Proposed (amendment 0.10.0) | ADR 0004; SQLite task-store ADR; migration spec §0.2 as corrected by the SQLite ADR | Cross-runtime contention/recovery/parity tests and CT-11 against one disposable PACER_HOME |
