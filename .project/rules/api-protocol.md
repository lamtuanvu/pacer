# API and protocol compatibility rules

Applies to: `src/api/**`, `src/serve/**`, `src/mcp/**`, `docs/protocol.md`, `docs/protocol-v2.md` and `scripts/protocol-doc.ts`. Also applies to any client that reads API results or events.
Out of scope: CLI human-readable output formatting. Where `--json` output exists, it is in scope.
Owner: @lamtuanvu
Canonical sources: [docs/protocol.md](../../docs/protocol.md), [docs/protocol-v2.md](../../docs/protocol-v2.md), `src/api/protocol.ts`, [CHANGELOG.md](../../CHANGELOG.md)

| ID | Rule or convention | Status | Rationale/source | Verification |
|----|--------------------|--------|------------------|--------------|
| API-1 | Adding a field does not bump the protocol version. Clients must ignore unknown fields. | Established | docs/protocol.md | Review client parsing |
| API-2 | Removing or renaming a field, op or event needs a major protocol bump (`src/api/protocol.ts`). The previous major is served through a compat adapter for one pacer minor release. | Established | docs/protocol.md; 3.0 + `src/api/v2-compat` | Review; compat tests |
| API-3 | The protocol docs are generated by `bun run protocol:doc` and committed. A stale doc fails the tests. | Established | `test/api-protocol-doc.test.ts` | `bun run test` |
| API-4 | Errors are `CoreError(code, message, hint?, data?)`, mapped to HTTP status and JSON-RPC codes as documented. New codes are added to the protocol doc. | Established | `src/core/errors.ts`; docs/protocol.md Errors | Review; tests |
| API-5 | No operation runs free-form text in a shell. An executor may delegate child work only through a service-issued task/attempt grant constrained to its own work subtree; executor sessions without a valid grant are refused. | Proposed amendment 0.13.0 for the scoped exception; prior blanket refusal established until maintainer merge | docs/protocol.md; constitution 0.13.0 | Review; grant and transport tests |
| API-6 | Breaking protocol changes and compat-window removals are listed in CHANGELOG under the release that ships them. | Established | CHANGELOG (Keep a Changelog) | Review CHANGELOG diff |
| API-7 | Each compat window names its removal release in CHANGELOG when it opens. For the current window, that means removing `/v2`, `protocol-v2.md` and `hello.previous`. | Proposed | The window currently says only "next minor" | Pending decision |

Relevant reviewers: [protocol-compat](../reviewers/protocol-compat.md), [security](../reviewers/security.md) (for transport/auth changes)
Exceptions and open decisions: API-7.
