# Security and secrets rules

Applies to: `src/serve/**`, `src/endpoints/**`, `src/usage/**`, `src/remote/**`, `src/exec/**`, `src/supervisor/**`, `src/session/**`, `src/install/**`, `src/update/**`, `src/service/**`, `desktop/**`, `.github/workflows/**`, `src/plugins/**`, `src/identity/**`, `src/discovery/**` and `$PACER_HOME/identity/**` (the last four added by amendment 0.17.0, proposed). Also applies to any new subprocess, network listener, file write under `PACER_HOME`, or secret.
Out of scope: purely presentational UI changes that touch no auth or data flow.
Owner: @lamtuanvu
Canonical sources: [SECURITY.md](../../SECURITY.md), [docs/accounts.md](../../docs/accounts.md), [docs/protocol.md](../../docs/protocol.md), [ADR app-web-ui](../../docs/decisions/2026-10-15-app-web-ui.md), [ADR remote-hosts-ssh](../../docs/decisions/2026-10-15-remote-hosts-ssh.md), [ADR 0012](../../docs/decisions/0012-machine-identity-and-paired-execution.md), [ADR 0013](../../docs/decisions/0013-lan-discovery-and-pairing-hand-over.md), `desktop/src-tauri/capabilities/README.md`

| ID | Rule or convention | Status | Rationale/source | Verification |
|----|--------------------|--------|------------------|--------------|
| SEC-1 | pacer never reads or copies the native credentials or Keychain entries of planner and executor tools. | Established | docs/accounts.md | Review `src/usage/**`, `src/install/**` |
| SEC-2 | Endpoint keys live in the macOS Keychain (service `pacer`), in `$PACER_HOME/secrets/<name>.key` (0600, dir 0700), or in env. They never appear in config, logs, events or API results, and are passed only to the child process as `PACER_KEY_<NAME>`. | Established | docs/accounts.md | Tests; grep the diff for key leakage |
| SEC-3 | The service binds to `127.0.0.1` only and checks the Host header (421 otherwise). Bearer auth uses a 0600 token compared in constant time. The app uses a cookie session from a single-use 60 s code (HttpOnly, SameSite=Strict). | Established | ADR app-web-ui; `src/serve/http.ts` | `test/serve-*` tests; review |
| SEC-4 | Non-GET app requests need a matching Origin and `X-Pacer-Client: app`. There is no CORS, bodies are capped at 256 KiB, and the app sends a CSP. | Established | docs/protocol.md; ADR app-web-ui | Tests; review |
| SEC-5 | Subprocesses get argument vectors, never shell strings built from user or API text. | Established | docs/protocol.md (API-5) | Review spawn sites |
| SEC-6 | SSH uses a BatchMode alias with `ConnectTimeout` and never copies credentials. A returned bundle is size- and identity-checked (≤ 50 MB, 1–500 commits). Live remote tests need separate maintainer approval. | Established | ADR remote-hosts-ssh; `src/remote/ssh.ts` | Tests; approval recorded |
| SEC-7 | Files with state or secrets are written atomically (temp file opened `wx`, then rename) with restrictive modes (0600 files, 0700 dirs). | Established | `src/activity/log.ts`, ADR app-web-ui | Review; tests |
| SEC-8 | Desktop has no static Tauri capabilities. Runtime capabilities are scoped to the exact service origin, and the CSP is `default-src 'self'`. | Established | desktop capabilities README | Review `desktop/src-tauri/**` |
| SEC-9 | CI actions are pinned to commit SHAs with `persist-credentials: false`. `pull_request_target` workflows never check out PR code. Gitleaks runs over the full history. | Established | `.github/workflows/*` | Review workflow diffs; CI |
| SEC-10 | Vulnerabilities are reported privately (GitHub Private Vulnerability Reporting), not in public issues. | Established | SECURITY.md | n/a |
| SEC-11 | The open host's only non-loopback listener is presence-only mDNS discovery: link-local answers only, bounded records, no machine id or OS user name, advertised only on networks the user approved, and it can be turned off. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §8; ADR 0013 | Discovery tests; review `src/discovery/**` |
| SEC-12 | Any other network listener belongs to a plugin holding `net.p2p`, authenticates peers mutually against pinned paired machine keys before forwarding anything, and forwards only through the peer socket with a peer credential; the peer socket refuses the owner token. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §7; ADR 0012 | Peer-socket tests; review |
| SEC-13 | Peer credentials scope the API surface by a named allow-list per tier; they are not privilege containment. They are hashed at rest, bound to one peer machine, minted only for a peer confirmed through the SAS contract, audited, and revocable with their streams. Operations carrying endpoint keys are never peer-callable. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §7; ADR 0012 | Tier conformance tests; review `src/serve/**`, `src/api/caller-policy.ts` |
| SEC-14 | Requests with a peer credential run only on runners that this machine owns and runs locally (no SSH host runners), and responses and events to a peer contain only such entries; no request or listing travels more than one machine. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §5; ADR 0012 | Three-home conformance test |
| SEC-15 | The host signs with the machine key only under the `pacer-machine-sig/v1` domain-separation format with a declared purpose, and logs each signature. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §1; ADR 0012 | Signing tests; review `src/identity/**` |
| SEC-16 | Discovered values are untrusted: sanitized before rendering, never used to build URLs or commands, and the pairing prompt can only start pairing; completion needs keys fixed first, a commitment binding both identities and transport keys, and the SAS computed from the transcript and rendered by the host, confirmed on both machines. | Proposed (0.17.0) | [Machine peers spec](../../docs/specs/2026-10-28-machine-peers-design.md) §8; ADR 0013 | Pairing contract and transcript tests; review |
