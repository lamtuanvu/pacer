## Scope (revised PR 5)

1. **Crash detection and reporting (G4):** owner dead-lane detection via the child's exit handle; drop the lane so `ensure` never returns a dead lane; a new `crashed` private IPC kind to the **owning door's** core (serve via `/_internal/plugins`, stdio via the sealed stdio kind) with a TypeScript twin of `recordCrash` so `restarts`, `error`, `nextStartAt` backoff and the three-crashes→`failing` rule stay Core-owned and match TypeScript. Attached stdio connections do not receive crash reports (documented divergence).
2. **Backoff:** Core seals the earliest start in `spawn_spec`; the owner delays `ensure` until then. Plus the **owner-side restart floor** (consecutive-crash ramp per plugin id) so an attached door whose core never saw the crash cannot respawn a crash-looping shared child at full rate.
3. **Teardown escalation:** explicit child termination with the TypeScript escalation (SIGTERM → 2 s → SIGKILL, matching `stopProcess` in `src/plugins/registry.ts`) at serve shutdown (`NativeHostSession::shutdown`) and at stdio connection teardown (EOF and SIGTERM) for the door's own children. No orphans.
4. **OD-7 productization:** bounded wait in `maybe_start` (~5 s at 250 ms cadence, test override env as the plan suggests) before refusing; stable greppable message naming the socket path and the remedy (`pacer service stop` or wait); **exit code 3**, documented beside the existing 1/2 convention; a `pacer doctor` check that probes `run/host.sock` (live → wait-or-stop remedy with the owner pid; stale → replaced on next start), with a `run/host.sock.pid` sidecar written at bind (0600, removed at shutdown) so the hint names the pid.
